# 《词弹碰碰局》微信小游戏发布前验收清单

此清单用于核心代码和自动构建完成后的最后一轮本地验证。当前构建产物已通过 GitHub Actions 静态检查和 Cocos Creator 3.8.8 自动构建，但尚未完成微信开发者工具与真机验收。

## 1. 导入构建包

1. 打开 GitHub Actions 的最新成功构建记录。
2. 下载 Artifact：**word-puck-ready-to-play**（如首传失败，选择 `word-puck-ready-to-play-retry`）。
3. 解压到本机目录，确认该目录直接包含 `project.config.json` 和 `game.json`；诊断日志在单独的 `word-puck-build-logs` 中。
4. 在微信开发者工具中选择「导入项目」，项目目录指向包含 project.config.json 和 game.json 的目录。
5. 首次预览可保留 Cocos 默认预览 AppID；正式上传前必须替换为自己的正式小程序 AppID。

## 2. 核心玩法检查

- [ ] 首次启动显示主菜单，包含开始游戏、玩法说明、图鉴和最高分。
- [ ] 点击开始游戏后显示竖屏场地、目标圈、计分 HUD 和 6 个汉字卡片。
- [ ] 玩法说明可正常打开和关闭，返回主菜单不误启动游戏。
- [ ] 初始字池至少提供 3 个有效组词选择。
- [ ] 选择两个字后，预览显示词语和对应弹药类型。
- [ ] 无效词语不能确认，也不能消耗字卡。
- [ ] 有效组词后消耗两个字并补入两个新字，字池始终保持 6 个字。
- [ ] 点击「提示」可预选有效词语，但不会自动耗费字卡。
- [ ] 点击「图鉴」可查看 24 个词语及已发现/待发现状态。
- [ ] 新词收录后图鉴计数更新，退出重进后收录状态仍然保留。
- [ ] 弹跳弹、磁吸弹、冰冻弹和冲击弹具有可感知的物理差异。
- [ ] 第二颗及之后弹药撞到旧弹药时，旧弹药**真的移动**，而非仅显示撞击特效。
- [ ] 撞击计数只在弹间真实接触时增加，墙面与固定机关不增加弹间计数。
- [ ] 弹跳弹碰旧弹药时反弹明显，没有穿透。
- [ ] 磁吸弹接近旧弹药时出现蓝色磁场，旧弹药向其产生位移。
- [ ] 冰冻弹撞上旧弹药后，旧弹药速度明显降低，显示冰冻描边。
- [ ] 冲击弹撞上旧弹药后，额外推动并显示红色冲击波。
- [ ] 瞄准线经过旧弹药时出现红色候选高亮，但遇到机关仍按真实物理为准。
- [ ] 按住弹药向后拖动可瞄准，松手发射；拖动距离能改变力度。
- [ ] 从圆盘边缘按下不造成方向跳变；轻微拖动不会误发射。
- [ ] 力度百分比按最低可用速度正确显示，并能控制中低力度。
- [ ] 彩色辅助轨迹在浅色场地清晰可辨，墙壁反弹预览与实际方向基本一致；障碍物和弹种效果仍以物理模拟为准。
- [ ] 第二根手指不能干扰已经开始的拖拽瞄准。
- [ ] 瞄准阶段组词面板背景与字卡都已隐藏。
- [ ] 暂停时场上弹药不再移动，继续后恢复运动。
- [ ] 暂停页“重新开始”“返回主页”操作正确。
- [ ] 后续弹药能够推动场上旧弹药，旧弹药得分会重新计算。
- [ ] 中心、中圈、外圈分别按 50、30、10 分结算。
- [ ] 命中增加连击，未命中增加失误；连续失误达到 5 次后进入结算。
- [ ] 结算界面展示本局得分、发射次数和本局发现词语数。
- [ ] 结算页“再来一局”和“返回主页”可分别正常执行。
- [ ] 点击重新开始后，场上对象、分数、连击、失误和本局图鉴计数均重置。

## 3. 机型与触摸检查

- [ ] 竖屏 720x1280 设计分辨率在微信开发者工具中正常显示。
- [ ] 在常见 9:16、较长屏幕比例和带安全区设备上检查布局。
- [ ] 汉字卡片、确认按钮和图鉴按钮均能准确点击。
- [ ] 最右侧汉字卡片与图鉴按钮之间无触摸区域重叠。
- [ ] 拖动发射时不会误触汉字卡片或图鉴按钮。
- [ ] 连续快速操作、连续碰撞和重新开始时无卡死或残留对象。
- [ ] 低性能设备上物理模拟和动画保持可接受帧率。

## 4. 配置正式 AppID

正式发布前，在 GitHub 仓库 Settings -> Secrets and variables -> Actions -> Variables 中新增：

| 变量 | 值 |
|---|---|
| WECHAT_APP_ID | 正式微信小程序 AppID，格式为 wx 加 16 位十六进制字符 |

自动构建脚本会将该变量写入构建产物的 project.config.json。未配置时继续使用 Cocos 默认预览 AppID，不可直接用于正式发布。

配置完成后，向 feature/puck-battle-prototype 分支提交一次正常代码更新，或在 GitHub Actions 中对该分支手动运行 workflow_dispatch，重新生成正式 AppID 对应的构建包。

## 5. 发布前检查

- [ ] 微信开发者工具中无编译错误和资源加载错误。
- [ ] 检查游戏名称、图标、隐私说明和必要的微信平台配置。
- [ ] 使用正式 AppID 重新构建。
- [ ] 上传体验版并邀请测试人员验证。
- [ ] 确认小游戏内容、权限、隐私和平台审核要求后再提交发布。
